## Controlled demonstration

```powershell
Set-Location C:\dev\GeetaStudio
pwsh -NoProfile -File scripts/verify.ps1 -Locked -LowMemory
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/db-update.ps1 -Database GeetaStudio_M1Tests -NoBuild
$env:GEETA_SQL_TESTS = '1'
try {
    dotnet test tests/ContentOS.Foundation.Tests --no-build --no-restore --filter 'FullyQualifiedName~SqlFactoryAiTests' --results-directory .local/prompt4-demo --logger 'trx;LogFileName=factory-ai.trx'
} finally { Remove-Item Env:GEETA_SQL_TESTS -ErrorAction SilentlyContinue }
```

They exercise recovery, budgets, cancellation, current rights/cast, malformed schema/citations and route pinning. Generated fiction starts as a pending M05 claim; only the test's explicitly labeled fixture review clears its evidence gate. No existing source permissions are broadened and no live provider is called.

## Staff interface and configuration

Apply the additive development migration without resetting/reseeding:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/db-update.ps1 -Database GeetaStudio_Dev -NoBuild
```

In the API terminal, enable the existing processors only when deliberately running a reviewed, permitted plan. These flags can execute already queued work:

```powershell
$env:Factory__WorkerEnabled = 'true'
$env:Workflows__WorkerEnabled = 'true'
dotnet run --project src/GeetaStudio.Api --no-build --launch-profile Development
```

In a second terminal: `dotnet run --project src/GeetaStudio.Web --no-build --launch-profile Development`. The general runtime worker is optional here: `dotnet run --project src/GeetaStudio.Worker --no-build --launch-profile Development`. M8 and factory processing run in the API. Use the existing staff/SQL provisioning in [LOCAL_DEVELOPMENT](LOCAL_DEVELOPMENT.md).

Open `http://localhost:5100/staff/factory` with the provisioned Windows staff account, or follow the factory link from `http://localhost:5200`. Choose the tenant/universe and reviewed lesson/cast, select **AI workflow**, choose a configured compatible definition, save and review a new plan revision, inspect the estimate, then start a bounded batch. Inspect work/child state, spent cost, outstanding reservations and worst-case allocation. Review the private draft in `/staff/editorial`, the generated-fiction claim in `/staff/evidence`, and the original child in `/staff/workflows`. Existing M12/M13 approvals and WATCH presentation/package/rights gates still apply.

A compatible definition requires `generated-text.v1`, evidence and mandatory human review, locale `en-IN` (existing M8 limitation), the lesson's exact audience and exactly five inputs: `brief`, `audience`, `cast`, `lesson`, `format`, each bounded to 2000 characters. An example prompt is `Write an original fictional script. Brief {{brief}} Audience {{audience}} Cast {{cast}} Lesson {{lesson}} Format {{format}}`.

Use existing scoped `POST /api/v1/workflows/tenants/{tenant}/universes/{universe}/prompts` and `/definitions`, with `RegisterPrompt`/`RegisterWorkflow` contracts in `src/ContentOS.Contracts/WorkflowContracts.cs`. Use Windows authentication, JSON and `X-ContentOS-Staff: 1`. The five steps are retrieve/plan/draft/check/review, with tools evidence.retrieve.v1/null/ai.generate.v1/null/null. Select an already-qualified M7 text route/profile and positive bounded cost, with `humanReview=true`. The new factory `GET .../generation-workflows` lists those definitions; it does not qualify routes.

The owned instruction requires outer `generated-text.v1` text/source IDs and inner `factory-script.v1` JSON with exactly schema/hook/scene/dialogue/decision/reflection. Dialogue contains only pinned characterId/text. Exact original anchor and interpretation claims are attached by owned code; author/tradition/locator/license remain in the immutable lesson and CMS citations. Generic existing text fixtures do not return this inner schema and correctly fail validation; use the controlled test demonstration above for repeatable successful fixture output. Live adapter quality needs deliberate credentials/profile/budget qualification in Prompt 7.

Every plan pins its definition/prompt/route/profiles and cast/evidence/schema. Route activation cannot replace an approved plan. Save and review a new plan revision selecting the new definition to switch future work; old work resumes its original workflow/AI operation. Batch generation currency comes from M7; media currency is a separate estimate. Worst-case allocation is item count times the pinned route run limit. Spent and unknown reservations come from M7, with no second ledger. Unknown usage stays blocked/reserved for existing M7 reconciliation; do not create a new paid operation to retry an ambiguous charge. Cancellation fences admission and signals claimed calls, while retaining unknown charges.

## VS Code debug

Open `C:\dev\GeetaStudio` as trusted, stop CLI hosts on ports 5100/5200, select **Geeta Studio: all**, and press F5. The existing API profile enables factory processing, so inspect queued work/rights/budgets first. Use Shift+F5 to stop the compound.

Useful breakpoints: FactoryExecution.ProcessNextAsync; FactoryGeneration.QueueGeneration; FactoryWorkflowFence.Bind/Validate; WorkflowRuntime.StartAsync; WorkflowExecution.ProcessNextAsync; AiService.Prepare/Attempt; WorkflowClaimCancellation; EvidenceEngine.SubmitInTransaction; EditorialWorkbench.StartAsync. Inspect original work, child and AI operation IDs, SQL transaction boundaries, current rights, reservations, pending claim and CMS draft.

For deterministic breakpoints, launch VS Code with `GEETA_SQL_TESTS=1` in its process environment and debug `SqlFactoryAiTests` in Test Explorer. Run that class alone and stop it before the full SQL suite. A fresh interactive F5/breakpoint, browser usability/accessibility review and live factory-to-WATCH demo are not established by these automated tests; see the milestone evidence for actual checks.
