## Configure an actual permitted feed later

First obtain a publisher's permitted public RSS 2.0 URL and actual permission/access documentation. Import/review the permission evidence and a suitable Read permission through the existing [source workbench](M3_LOCAL_RUN.md). Keep source rights, locale/territory and retention restrictions explicit. A publicly visible link alone supplies no license, transcript, independently verified claim or AI permission.

Only a trusted host operator can configure `Trends:RssFeeds` (merge into existing local configuration; do not replace secrets or staff mappings). This disabled example is intentionally unusable until its URL, zero snapshot ID and reference are replaced with genuine reviewed values:

The example is not an invented approved feed. Keep Enabled false until a permitted source is supplied and reviewed. URL credentials and private destinations are unsupported. No HTTP credential or paid account is used. When approved, use a new immutable profile key/reviewed connector version for a binding change. Replacing an existing profile's URL, permission snapshot or reference will reject old connectors rather than silently move them to a new source. Updating host configuration requires restarting the API.

Register a connector through `/staff/trends` using operation path `connectors`, or authenticated `POST /api/v1/trends/tenants/{tenant}/universes/{universe}/connectors` with `X-ContentOS-Staff: 1`. Its existing RegisterTrendConnector request uses:

- sourceAdapter `trend.configured-rss.v1`, extractorAdapter `trend.owned-text.a.v1`, mode `Manual`, actual manual evidence reference, fixtureSignals `[]`.
- feedSnapshotId equal to the profile's reviewed permission snapshot ID, with permitted feedLocale/feedRegion.
- liveFeed containing the exact configured Binding fields (key/url/permissionSnapshotId/permissionReference).
- explicit key/version and a stable operationId. The default locale/region remain en-IN/IN; select only permitted supported values.

Poll using operation path `poll` with `{ "operationId": "<new GUID>", "connectorId": "<registered connector ID>" }`. These placeholders are request instructions, not completed source records. Retrying the same operation reuses its accepted result without another fetch. A new poll operation fetches once and reuses unchanged candidate IDs; source time/content/metric changes append versions. Each poll has one attempt, no redirects, a bounded total deadline and body/header limits. No background discovery poll was added.

The transport accepts only the exact configured HTTPS destination on port 443. It disables proxies, cookies, credentials, redirects and decompression; validates every DNS answer at connection time; and connects to the selected validated IP with normal TLS hostname/certificate validation. Private/link-local/metadata, mapped and transition addresses are rejected. Allowed response types are application/rss+xml, application/xml and text/xml. DTDs/entities are prohibited. This deliberately bounded path does not claim compatibility with every publisher's RSS/HTTP configuration.

Run the API using `dotnet run --project src/GeetaStudio.Api --no-build --launch-profile Development` and open `http://localhost:5100/staff/trends`; the Blazor shell is `http://localhost:5200` when run separately. Staff authentication/scope and private cache behavior remain mandatory. Read the connector coverage and candidate metadata, source/retrieval times, content hash and blockers. Feed summaries/enclosures are never downloaded as articles or treated as factual substance. A changed item gets a new version without overwriting the old one; at 25 observations, new work fails visibly rather than deleting history. A durable safety hold/remediation and rejected-observation digest commit even on that failure; a retraction still propagates correction. Repeated rejected versions reuse the recorded failure/digest without duplicate correction tasks. An unchanged accepted version remains reusable at capacity. Once a newer observation has been rejected at the limit, a persistent proof blocker prevents reapproval using only the retained older evidence; append a fresh reviewed source/event version.

The original retrieval time stays on its immutable candidate. Every accepted poll retains its own operation/audit timestamp and resulting IDs, including unchanged polls. The poll's local clock is excluded from semantic identity. Metrics retain their own observation times; RSS supplies no invented view counts. New connector revisions are intentional source bindings and need review. Disable/cancellation/permission changes are checked again before accepting fetched metadata. Current feed permission withdrawal withholds returned headlines/URLs and blocks downstream use.
