## Plan longer approved narration

Use normal `CreateWatch` JSON with ordered full script spans and actual character/presentation bindings. A long part needs an existing reviewed image and a `voiceGeneration` prototype using the approved original speech profile. Its `promptOrText` must exactly equal the entire part text. Supply real permission metadata; placeholders and fixture references are not rights.

POST to `/api/v1/watch/tenants/{tenant}/universes/{universe}/narration-plan` with staff authentication and `X-ContentOS-Staff: 1`, or select **Plan narration segments** in advanced WATCH administration. The response is an ordinary `CreateWatch` request. Inspect it, then explicitly submit to `/productions`. Planning creates no production, media job, approval or charge.

The planner preserves every UTF-16 span/grapheme and all whitespace, prefers word boundaries, and returns at most 24 segments within the provider ceiling of 160 characters for a script of at most 3,200 characters. It budgets caption lines below the image using the reviewed font/margins and requested aspects: default limits are 60 characters for vertical and 80 for standard, with smaller segments for larger fonts/margins. Long part keys allow 60 characters for bounded suffixes; existing bounded scenes retain their 80-character keys. Segment operation/output identities derive from the original request and part/offset. Ordinary WATCH execution pins each original stage/segment M16 job and records each reservation/cost. Replanning is deterministic; context is never silently truncated.

An imported whole recording cannot be repeated across split captions: provide reviewed per-segment recordings or a permitted exact speech profile. Image generation is not multiplied across segments; import/generate and review the image first. Multiple speakers need explicit ordered parts with their own bindings.

Existing timing gates remain: PCM WAV up to 30 seconds/1 MiB, complete scene-level captions/credits, frame timing/reading-rate limits, vertical 60 seconds, standard 120 seconds and original budgets/deadlines. Planning does not guarantee the script fits a selected aspect; excessive duration requires an independently reviewed shorter script. No ASR, word alignment or generative-video dependency was added.

## Speech receipts and compatibility

An exclusive operation lock, canonical request marker and accepted WAV checksum/length receipt prevent duplicate or changed-input synthesis. Accepted receipts survive restart and reuse original bytes; a missing installed token cannot authorize new synthesis. Changed text, locale, pronunciation, bounds or corrupted bytes cannot replace the original operation. Cancellation/ambiguity remains Unknown and never blindly resubmits.

SAPI uses the exact token, asynchronous plain-text speech, bounded pronunciation expansion, 30-second cancellation deadline and byte limit. Cancellation purges speech and closes/releases resources before completion. Atomic receipt publication protects accepted outputs. A crash before receipt publication or a legacy WAV without a receipt requires original reconciliation/review, not automatic adoption/regeneration.
