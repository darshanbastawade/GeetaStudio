## Diagnosed cause

The previous release-check script checked whether milestone Markdown files existed, then emitted a fixed blocker list and productionReady=false. It did not evaluate current selected-resource evidence or enforce a manifest at direct API URLs. An operator could not obtain a feature-specific decision bound to the actual candidate.

## Behavior implemented

The proposed, unapproved scope is READ/WATCH/manual export. Disabled TALK/voice, payments, B2B, automatic publishing, CREATE and analytics have no required optional live approvals. Enabling unsupported pilot features blocks the decision. Selected features need exact tenant/universe/resource/evaluation targets. Each decision binds compiled code, policy, effective configuration and complete manifest bytes to current module content/provider versions and operational reports. Per-target/module reasons and references are included; one blocked feature does not independently qualify itself or erase another feature's blockers.

Existing READ/M12/WATCH/M18 ports recheck human qualification, exact audience/body, current source/media/approval and export rights, original renderer binding and media versions. Source snapshot/permission/revocation state contributes to the binding. Manual packages must use a reviewed ExportOnly account and their selected WATCH dependency. Operational reports must also meet measured criteria (including recovery limits, non-vacuous complete CI counts and zero high/critical findings); Human reports require a named reviewer reference. A Passed label alone is insufficient. Operational evidence is a SHA256-bound, expiring index of genuine owner/security/usability reviews and hosting/monitoring/recovery/CI/provider applicability reports, not a new source registry, evaluation ledger or ready flag. Fixture reports cannot replace those requirements. No real reports are fabricated; targets and operational receipts remain empty.

Production/Staging route enforcement cannot be disabled by a configuration boolean. Only qualified selected READ keys/IDs, authenticated selected WATCH read/export resources and M18 manual export are admitted. Other staff/API routes stay unavailable, including authoring and automatic effects. Existing module authorization remains authoritative. Development retains the private workbench by default; optional enforcement is available. API background processors are suppressed in enforced pilot mode, and the standalone execution Worker refuses enabled runtime outside Development. Existing public Web data still comes from the gated API. Check-only shares the same evaluator and never starts HTTP/hosted workers.
