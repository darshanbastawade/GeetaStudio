## Diagnosed gaps and implementation

Existing `ITrendSource` supported only synchronous fixture/uploaded RSS discovery. Network I/O inside the old poll command would hold a SQL transaction. Different poll operation IDs appended unchanged candidates and changed the cluster's review fingerprint. Trend preparation selected `IFactoryTemplate.Single` unconditionally, preventing the optional AI factory mode from Prompt 4.

The existing typed source port now supports asynchronous discovery with default compatibility for existing sources. `ConfiguredRssTrendSource` is registered in the API and resolves only an operator-configured, enabled `Trends:RssFeeds` binding. A connector pins its exact key/HTTPS URL/reviewed permission snapshot/reference. Missing, changed, disabled or cross-scope bindings are rejected. The normal configuration has no live feed; defaults cannot fetch.

The transport has one owned attempt, no redirects/proxy/cookies/credentials/decompression, HTTPS port443 only, normal TLS validation, a total 1–30 second deadline, at most 65,536 body bytes and 16 KiB of headers. DNS is checked at connection time; every answer must pass the conservative public-address policy. It connects to the selected validated IP rather than resolving the host again. Mixed public/private answers, loopback, link-local, shared/private, metadata, mapped-private, documentation and transition destinations are denied. Source article/enclosure links are never fetched. XML DTDs/external entities are prohibited and document size is bounded.

RSS2.0 yields at most 25 candidate metadata entries: stable opaque source-ID hash, canonical URL, source publication time, first retrieval/observation time, coverage and item-content hash. Descriptions contribute only to the version hash; they are never invented transcripts, retained article substance or approved factual claims. RSS supplies no made-up metrics. Unsupported content types, redirects, oversized/malformed responses, unavailable substance and timeouts fail explicitly.

Polling checks current staff scope, connector and source permission before HTTP, performs HTTP outside SQL transactions, then rechecks under the existing tenant trend lock before accepting. Accepted poll replay returns its original IDs without fetching again. New poll IDs reuse the original candidate for unchanged semantic observations, ignoring only local poll time while retaining source timestamps and metric observation times. Reuse chooses the earliest matching legacy record deterministically; existing duplicate records are preserved. Each poll still has its own operation/audit time and resulting IDs.

Changed observations append immutable versions, hold affected briefs and request editorial review. Genuine source correction/retraction uses existing correction/remediation. Ordinary metadata/metric changes do not falsely correct a supported central claim. The 25-observation cap never deletes history: an unrecordable new change commits a safety hold and rejected-version digest, then returns a visible capacity error. A retraction still propagates correction at capacity. Repeated failed versions reuse the failure/digest without duplicate remediation. The same accepted operation replays without another HTTP request. A persistent proof blocker prevents renewing approval over retained evidence after a rejected observation; a fresh reviewed source/event version is required. Internal failed-result markers are never exposed as candidate IDs.

Current feed-permission withdrawal blocks polling and redacts returned candidate headlines/URLs, independently of substance rights. Existing stale-event, independent corroboration, claim/correction, sensitive-topic, no-match, cast and human review gates remain in force. Uploaded RSS/manual intake remain available.

An approved trend brief can now select the same optional AI factory plan as Prompt 4. Preparation shows an explicit pending-script placeholder and spends nothing. The shared factory owns generation, original M8/M7 operation recovery, costs and private M13 review; no second story engine exists. Generated fiction remains a pending claim and the factual prefix/source/cast/AI lineage is complete.
