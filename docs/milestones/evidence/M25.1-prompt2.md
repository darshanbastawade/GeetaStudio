## Cause and proof before the fix

The audit hypothesis is confirmed. `LinkAsync` captures the entire KnowledgeResult. `TeachingView` formerly returned it when the selected lesson was not withheld, without validating every saved hit. A different source could become ineligible while that lesson remained valid. `TrendStorySnapshot` embeds the same retrieval, but the old story fence checked selected teaching/event/scripture sources without checking additional hits.

Normal-operation real-SQL tests proved both leaks before production code changed. The decisive decoded-field regression run returned two failures and one eligible-data control pass, with no skips. Tests inspect every decoded JSON scalar, including Unicode-escaped text and copied rationale/alternatives, and use generic failure messages that do not echo restricted passages. Logs/TRX: `.local/M25-1-prompt2/red-decoded.log` and `results/red-decoded.trx`. An earlier run independently failed the missing-withholding assertions. A missing namespace import in the first implementation build was corrected before the passing build.

## Implemented fix

- `KnowledgeService.cs` / `KnowledgeStoredEvidence.cs`: reuse the existing corpus eligibility and graph/current-claim checks for stored results. Validate the pinned tenant/universe/index, validation state, locale/territory/intended use, embedding profile, chunk/text/manifest/version/locator/hash/span, exact quotation and current citation/permission binding. Current editorial claim corrections now also invalidate graph evidence. No embedding/ranking/provider call or alias refresh occurs during revalidation.
- `TrendWorkbench.cs` / `TrendStoredEvidence.cs`: teaching reads use a serializable projection boundary, joining an existing transaction where present. Any blocked evidence withholds the whole retrieval plus potentially copied rationale/alternatives; historical outcome, IDs and audit/snapshot records remain intact. Eligible results and genuine empty no-match results remain unchanged.
- `TrendStories.cs` / `TrendFence.cs`: recheck stored teaching and copied story retrieval at read, prepare completion, renewed review, binding and existing downstream brief/plan/revision fences. Withhold the entire story snapshot when blocked. Automatic recheck holds affected briefs and queues editorial review. Retrieval-only invalidation does not falsely correct the still-valid event claim.
- `TrendTestFixture.cs` / `SqlTrendStoredEvidenceTests.cs`: allow a guarded local embedding fixture and add three permanent SQL regressions. The fixture throws if embedding is attempted after storage, proving revalidation has no new provider call.

No public contracts, adapters, generators, SDK/package pins, locks, entities or migrations changed. No database reset or production SQL. Immutable teaching/story JSON hashes are asserted unchanged after projection and correction review.

## Regression coverage and model limits

1. **Independent source B, no match:** selected lesson A stays valid; B has a separately registered test work/edition, exact existing two-verse Besant sample, normal corpus/index validation and alias activation. Revoke B through the source registry, switch the live alias to valid A, then read/replay the saved lookup. B's text is absent from all response fields, the old no-match outcome remains honest, no new retrieval runs and the saved snapshot hash/identity remains unchanged. Foreign-tenant access is denied.
2. **Matched lookup with additional hit and story:** an actual two-hit query selects lesson A/verse1 while retaining verse2 as an additional hit. A normal editorial source correction targets only that extra snapshot. The lesson remains readable; teaching and story output are withheld, renewed teaching/story review and new reuse fail, and recheck holds the brief for editorial review without creating an unrelated event-claim correction. Stored story hash is unchanged.
3. **Eligible/empty controls and index switch:** eligible teaching/story and an actual pizza no-match lookup remain readable after an alias switches to a different validated index. They retain the original stored index rather than fetching replacement evidence. Embedding remains forbidden on reads.

The model requires one source edition per component locale inside a scripture manifest. Therefore the matched additional-hit case correctly uses distinct snapshots from the same edition; it does not invent an unsupported mixed-edition manifest. The no-match case uses an independent manifest/work to prove independent source revocation. Snapshot, corpus and concept reviews are frozen after approval; tests do not mutate reviewed rows directly to simulate impossible withdrawal. Revalidation still uses the existing current corpus review/binding checks; source revocation and permanent editorial correction are exercised through real application operations.
