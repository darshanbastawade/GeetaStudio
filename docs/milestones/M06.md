# M06 — Concept Graph and Portable Knowledge Retrieval

## Status and scope

**Offline Verified**, 10 October 2026, on real local SQL Server and Windows-authenticated API/web hosts. M0–M05 preserved. Live sandbox N/A for a new external provider: local approved code only. Production not qualified. **M07 not started.**

M06 supplies one production-intended local SQL hybrid retrieval path and an independent deterministic fixture ranking adapter. The semantic path uses reviewed concepts/aliases/relationships projected into normalized feature vectors. It is not a pretrained neural model or a claim of general multilingual semantic competence.

## Implemented behavior

Owned IKnowledgeRetriever, IEmbeddingProvider, IKnowledgeRankingAdapter, IKnowledgeAdministration and IKnowledgeIndexWorker contracts separate policy, SQL persistence and deployed adapters. Concepts carry explicit locale/name/alias/translation terms and scoped source/optional claim provenance. Related/Broader/Contrasts edges start Pending and require staff review; generated text cannot silently approve a relationship.

Versioned indexes pin selected corpus material, manifest/version, reviewed graph, locale, model/version, 128 dimensions, L2 normalization and verse-component-v1 chunking. Stable chunk IDs derive from immutable corpus text IDs/policy. EmbeddingSpaceId includes corpus material and graph/model/settings; equal dimensions never authorize a different model. Query vectors use the pinned profile. Index and vector/response contracts reject incompatible or invented chunk IDs.

Local lexical matching uses normalized tokens, limited English inflection handling and inverse document-frequency weights. Reviewed alias/one-hop graph projection supplies the configured semantic path; hash collisions alone cannot create a supported match. The independent fixture adapter uses a separate rarity-weighted feature-count algorithm, preserving the owned source response contract. No optional reranker is selected; no unused external provider port/SDK was introduced.

Only approved, retained, selected-edition-bound exact corpus components qualify. Owning-tenant membership and current source rights/intended use are checked before ranking; restricted rows never enter returned evidence/citations. Graph/relationship and all optional claim evidence dependencies are checked; supersession/open corrections/restriction block a stale pinned graph. Returned evidence includes stable source/chunk/text IDs, source-snapshot UTF-16 offsets, edition/verse/version, SHA-256, current citation/permission/attribution and index/model metadata. Scores rank evidence, not factual certainty.

A durable SQL queue is processed by an API-hosted background worker using existing source-read privileges. Chunk publication and Ready state commit atomically; interruption rolls back to Queued and can resume with the pinned space. Operational failures become Failed with redacted reasons. The separately runnable M01 Worker retains runtime-only SQL privileges. No remote side effect, credential or paid call is added.

Shadow evaluation records known-positive and no-answer labeled questions without changing the alias. Passing validation and current eligibility are required for atomic rowversion-controlled activation and rollback; incompatible spaces, stale validation and newly failed shadow revalidation block use. Old indexes/chunks remain retained.

The staff /staff/knowledge page and Blazor link support source evidence search, graph/index inspection and administrator forms. Windows staff policy, actual owning membership and action-header protection apply. Append-only command/audit rows retain operation replay and operational events; telemetry logs exception types rather than source/query/secrets.
