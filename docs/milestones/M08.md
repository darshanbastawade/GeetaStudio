## Implemented behavior

Owned PromptRevision/WorkflowDefinition artifacts model key/version, declared bounded inputs, locale/audience, output schema, evidence requirements, closed steps/tools, recovery-attempt limits, cost/currency/token/deadline/lease limits and mandatory review. Identical registration is idempotent; conflicting revision content fails. Existing prompts, definitions, run snapshots and accepted checkpoints are immutable.

IWorkflowRuntime/IWorkflowWorker and the five SQL workflow tables own canonical bounded inputs/results, immutable prompt/definition/route/profile snapshots, ordered checkpoints, external-operation IDs/bindings and append-only control decisions independently of any orchestration vendor. The first runtime is owned-sequence.v1: retrieve → plan → draft → check → review. An evidence-required miss fails NoSupportedMatch; a declared original-fiction workflow may proceed without retrieved sources. No generated plan can change the sequence or bypass review.

The capability-limited IToolInvoker registry exposes evidence.retrieve.v1 and ai.generate.v1 through typed methods. It has no arbitrary URL, shell, MCP dispatch or model-selected action. Tool/source text is bounded and JSON-delimited data; recognized hostile instructions, extra/looping plan fields and unknown/foreign source IDs are rejected before checkpoint acceptance. Current owner membership, source rights and optional existing M05 content/claim eligibility are rechecked at generation/check/review/inspection. Revocation withholds checkpoint output. M05's existing transaction-aware gate participates in the parent review transaction.

Serializable claims/application locking and persisted lease tokens fence late completion. Pause/resume is allowed at completed-step boundaries within the original deadline; cancellation fences unfinished checkpoints. Every successful draft waits at AwaitingReview. Staff review records an explicit evidence reference, rowversion and idempotent operation; approval finishes this draft workflow and does not publish or approve canonical scripture.

One draft checkpoint owns one M07 operation ID and its entire bounded fallback-chain reservation. Definitions cover its run/currency/token limits. Admitted cancellation or crash retains the original AI ledger binding/accounting. Settled accepted AI output is reused after interruption; in-progress/unknown usage blocks for authoritative reconciliation, never a new provider submission or fabricated zero usage. A reconciliation without eligible successful output cannot resume generation.

Retrieval permits historical local concept-projection-v1/v2 spaces only, so remote embedding charges cannot escape the workflow total cost bound. Remote retrieval needs an explicit reviewed accounting extension. The API-hosted WorkflowProcessor uses the existing restricted API content/source/AI identity; the separate M01 Worker keeps runtime-only permissions.

Checkpoint exports use workflow-checkpoint.v1 at paused/terminal boundaries. Alternative-engine drain/import requirements are documented in [M8_LOCAL_RUN](../M8_LOCAL_RUN.md); no generic importer or third-party engine was introduced or tested.
